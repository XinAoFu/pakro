## 重构原则

1. **尽量复用**：已符合要求且功能存在的代码保留；优先调整入口、所有权、输入输出和调用关系，不重写 PEP440、Simple、PubGrub、Rattler、wheel 校验等现成内核。
2. **先接通，再删除**：每条删除都有替代任务、现存消费者和验收门。新文件存在不等于替代完成；必须是真实入口已调用、用户验证有结果，再退役旧路径。
3. **不同命令不合并**：保留既有独立职责，不合并不同命令；六项 install 记录中的旧 migrate 本轮不扩建，其余五项与四个 uninstall、十四个查询入口继续实施。D04 辅助命令全部保留。没有九入口方案，也不新加统一 find 命令。
4. **真实共享**：同精确语言全机只一份实际 payload；ProjectId 不进入共享内容身份。A/B 引用与可写投影独立，不能以校验、构建或隔离为理由每项目长期复制一套 Python。
5. **未提交改动也是现状**：工作树已有大量修改和未跟踪实现；基线含这些文件。不得回退到 HEAD、覆盖它们或批量恢复用户清理的 docs。
6. **模块迁移不制造双份实现**：从旧文件提取的函数由旧/新调用者暂时共用一个内核；迁移完删旧转发或旧正文，不长期维护两个 parser/下载器/引用权威。
7. **不自动删用户数据**：本计划的 Delete 指代码与专属资源。旧安装目录、下载缓存、Git历史和用户项目数据另按批准的迁移/清理政策处理。
8. **不把中途切线当完整交付**：R16只形成第一条wheel纵向管线；源码、editable、Conda、Java/Node、内部操作保护和整体验收仍分别记录；IDE/外部运行接入单独后置，不能宣布全部完成。
9. 分阶段出现尚未接生产消费者的警告时如实记录，不用 allow、空调用、假证明或删测试消除；最终质量门必须在实际接线后通过。

### D04：缓存是什么，三条命令各做什么

正式库是“实际使用的 Python 和包”，缓存是“获取、查询和准备它们时留下的中间材料”：

- **下载暂存**：一个安装包下载到一半还不能作为完整安装使用，先放受控临时位置，下载完并核验后才发布。中断可能留下可清理的残片。
- **版本与依赖信息**：例如“Python 有哪些版本”“requests 依赖哪些包”。把远端回答暂存起来，下一次不用重新问服务器，查询和安装更快。
- **可复用的获取/构建中间结果**：避免重做已完成的工作。不是给每个项目再装一套可运行的 Python，也不是所有压缩包都可随便删；属于正式包库或仍受引用保护的输入不能当普通缓存。

| 命令 | 大白话说明 |
| --- | --- |
| `pakro cache path` | 告诉你缓存文件夹在哪，不删除内容。 |
| `pakro cache clear` | 清掉可丢弃缓存；之后需要时重新获取或生成，下一次可能慢一些。当前实现支持指定工具；重构须保护在途操作和正式库。 |
| `pakro cache prune` | 按规则只清理陈旧缓存。当前源码按多久没访问筛选，普通缓存默认 30 天；环境计算缓存另有过期规则。它不按项目引用卸载语言或包。 |
| `pakro prune` | 用户主动调用后，找出没有项目引用的正式受管内容并清理，与缓存清理不同。 |

缓存和正式库都在 Pakro 受控存储内。cache clear/prune 不得删除正式语言/包、锁、项目登记或恢复记录；在途操作用的暂存也不能被破坏。缓存清掉后重新获取可能需要网络，不把“没有缓存”误报成“没有可用版本”。

其他辅助命令原职责保留：doctor 组与 test-tool 负责诊断或执行检查；env 输出环境信息；installs select 选择已有实例；version/self-update/implode 维护 Pakro 本身。保留它们不恢复已排除的通用 task、cache task 或系统管理功能。self-update 仍须如实报告发行配置缺失，不能声称发布设施已经可用。

### D06：用户选包，用户决定何时清理

1. 不自动读取默认常用包清单并安装 ipython、black 等，也不自动把旧清单变成项目依赖。用户明确选择包后，它正常工作所必需的依赖仍要一起安装；这些依赖不是额外推荐的常用包。
2. 用户显式执行 `pakro prune` 时，自动筛选没有任何项目直接或间接引用的受管内容。比如提前安装 Python 3.11 但没有项目选用，它就是可清理候选；曾经手工下载不是永久保留理由。
3. 不执行 prune 就不触发这项全库清理；普通 install/use/upgrade/unuse/deps remove 不暗中运行 prune。本次操作自己拥有的失败暂存和事务收尾仍正常处理。
