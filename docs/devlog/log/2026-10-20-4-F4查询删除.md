### Standards：边界、保护与复用

- 查询只读与写入/删除入口分离；CLI 只持请求与描述性报告，不能取得任意路径删除许可。独立 bin 的旧工具分类通过小型纯 public facade，未公开 registry/IO owner。其它旧生态查询职责保留。
- 正式对象使用专属私有字段 RemovalPermit；没有借用旧未提交暂存 cleanup 的权限。稳定锁均位于 allocation 之外，删除 kernel 无对应删除操作。目录遍历校验 normal components、fd 身份、受管 root 与 inventory；capture 使用 R05 no-clobber rename。
- package catalog 的最终 EX 检查直接复用现有 control，避免同进程再开 SH 自锁。派生 adapter 先在 catalog 外排序 try-acquire 实际 EX；正在用则保守拒绝，未在持 catalog 后等待对象锁。
- 事实来源已对齐：query 的 enumerate→acquire→PackageLease.check_binding、删除 EX 中的 `validate_package_facts(&permit.root,target)`、最终引用读取中每个保留 parent，均使用同一个 `lease::validate_package_facts`。该核绑定 root identity、inventory 中的保留事实文件 inode/类型/大小/0600 权限/SHA256，并将有界 no-follow 读取字节与 canonical facts+language+filename 对照；有效 JSON 标签不能绕过实际发布树。
- 引用读取有条目/字节上限（累计 64 MiB）与原请求 deadline 检查；失读、损坏、缺依赖直接报错，不以默认空集合继续删除。没有新引用计数权威或另一套 projects.json 删除判据。
