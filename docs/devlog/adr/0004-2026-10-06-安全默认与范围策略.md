# ADR-0004 安全默认与范围策略：wheel-only、不执行安装脚本、精确版本铁律

接管包管理即接管供应链风险（pip/npm 的安装期会执行包内任意代码）。决定三条默认策略：(1) python 第一阶段仅安装 wheel（预编译包，只需解压、零代码执行），遇到纯源码包明确报错说明，源码构建延后；(2) npm 的 pre/postinstall 生命周期脚本默认跳过（显式开关后补）；(3) 一切版本声明精确（`3.10.14` 而非 `3.10`），注册表声明的产物哈希入锁、下载强校验。哈希/签名校验复用仓库内 sigstore/packslip 体系。用户 2026-10-06 会话中逐条给出这些约束并批准。

## Considered Options

| 候选                          | 说明                   | 取舍                                                                       |
| ----------------------------- | ---------------------- | -------------------------------------------------------------------------- |
| wheel-only + 跳过脚本（选定） | 供应链攻击面压到最小   | 部分纯源码包第一期间不可用（明确报错）；换来的是默认比 pip/npm 更安全      |
| 全功能（sdist+脚本）          | 覆盖全部包             | 要实现 PEP 517 构建协议 + 默认执行任意代码，工作量与风险双高，违反渐进原则 |
| 内嵌 pip/uv 子进程兜底        | "原生优先，兜底走旧路" | 违反"全程不经外部包管理器"的硬需求（FR-2），且两套行为不可预测             |

## Consequences

- 第一阶段不支持清单要在报错信息与文档中明示（哪些包只有 sdist）。
- 精确版本意味着没有 `^`/`~` 顶层语法；用户改主意的成本是未来一次 ADR（范围约束作为显式可选层）。
- 差分测试中 uv/npm 的"范围解"需先固化为精确顶层再对照（方法论细节，M1 处理）。

## 补充（2026-10-07）

node 组键语法定为 `node@22.14.0`（与 python 统一为 `名字@精确版本`），推翻设计文档中 `node-22.14.0` 的示例写法——统一语法让 requests_from_config 的严格校验无需生态特判。来源：M2 规划时发现原示例写法无法通过组键解析（不含 '@'）。
