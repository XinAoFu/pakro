# ADR-0002 解析器：pubgrub 算法 + 各生态官方版本语义库

mise 现有代码明文禁止假设版本遵循 semver（AGENTS.md 铁律），而包解析必须处理版本范围约束，二者正面冲突。决定：版本语义知识全部收敛到 `mise-resolver` 内部的"生态适配层"——每个生态注入自己的版本表示与比较规则；顶层版本由用户精确指定（不猜），传递依赖由求解器解出（唯一确定结果）。求解算法采用 **pubgrub**（crates.io `pubgrub` crate）；python 侧用 **pep440_rs + pep508_rs**（uv 作者维护，uv 的解析器即建于此），node 侧用 **node-semver**，go 侧不用求解器（MVS 规则简单，纯函数实现）。用户 2026-10-06 会话批准（方法论要求："直接拿来用，避免重复造轮子"）。

## Considered Options

| 候选            | 说明                                            | 取舍                                                                             |
| --------------- | ----------------------------------------------- | -------------------------------------------------------------------------------- |
| pubgrub（选定） | Cargo/uv/Dart pub 同源算法；纯 Rust；crate 活跃 | 生态验证最充分；错误报告（冲突诊断）质量高                                       |
| resolvo         | rattler/conda 系的求解器 crate                  | 同为 pubgrub 变体，conda 系验证；但对 python 外生态的通用适配示例少              |
| 自研回溯求解    | 完全手写                                        | 无必要：这是被反复解决的问题，自研大概率重蹈版本求解经典坑（冲突循环、指数爆炸） |

## Consequences

- 与 AGENTS.md 铁律的相容性声明：铁律约束的是"工具层挑版本"的调用点；`mise-resolver` 内部的语义适配层是版本知识的唯一所在地，不散落。此解释已写入架构文档第二节。
- pubgrub 的版本抽象需要为每个生态实现 Set/Version 适配（python 经 pep440_rs、node 经 node-semver 转换）；这是 M1 的主要工作量之一。
- 差分测试（对照 uv/npm）成为 resolver 的验收手段，而非运行时依赖。
