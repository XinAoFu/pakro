# ADR-0003 存储：全局内容寻址仓库 + 符号链接物化，不做 Windows

跨项目共享安装结果（用户核心需求）要求"相同的东西磁盘上只有一份"。决定：包按身份（名字@精确版本×运行时×平台×产物 sha256）落盘于 `~/.local/share/mise/store/<生态>/<名字>/<版本>/<digest>/`；项目内物化为指向 store 的符号链接——python 生成标准 venv 形状目录（自建 pyvenv.cfg/bin/site-packages，不调用 python -m venv、不装 pip），node 生成链接式 node_modules（内含 `.mise-store/` 私有目录承载多版本传递依赖，顶层链接指向直接依赖）。因用户明确声明本项目不做 Windows（2026-10-06），无降级分支负担；Windows 重评估时再引入 junction/拷贝策略（写新 ADR）。

## Considered Options

| 候选                            | 说明                     | 取舍                                                           |
| ------------------------------- | ------------------------ | -------------------------------------------------------------- |
| CAS store + symlink（选定）     | Nix/pnpm/uv 验证过的模型 | 去重绝对可靠（哈希即身份）；物化成本是建链接                   |
| 每项目独立环境（pip/venv 现状） | 无跨项目共享             | 直接违反需求                                                   |
| 硬链接共享                      | 无符号语义               | 目录结构上不可行（硬链接不指向目录）；被 uv 用但仅限文件级缓存 |

## Consequences

- 卸载语义从"删目录"变为"引用计数归零才真删"（`mise store gc`）；需要 refs 跟踪与陈旧条目回收。
- venv 形状由 mise 自己生成：必须正确写 pyvenv.cfg 的 home 指向 installs 下的解释器；此结构 uv 已验证可行，实现时以其行为为参照。
- 生成的环境内无 pip 是刻意的防漂移措施（SPEC FR-7）。
